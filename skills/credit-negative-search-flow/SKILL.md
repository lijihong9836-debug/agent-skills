# 授信负面信息检索与证据流程

## 依赖与项目适配

本技能与 `credit-negative-monitoring` 配套安装；同级目录可使用下文相对链接，分开安装时按技能名称定位其实际 `SKILL.md`。业务规则由监测技能及其参考文件维护。文中 `tools/` 路径相对于用户业务项目根目录，属于可选项目实现，不随本技能分发；存在时先核对接口与规则一致性，缺失时按同一规则执行可独立完成的核验和处理，明确记录无法运行的程序验收。规则不可读时按第4节保留待处理状态。

## 1. 确定工作模式

根据用户本次任务选择模式，并沿用已经明确的授权。用户要求只检索、只核验或只提方案时，交付到对应阶段；要求完成监测表时，继续完成归集、回写和验收。

| 模式 | 执行范围 | 结果标识 |
|---|---|---|
| 联网检索 | 按冻结范围逐家检索，打开原始来源核验候选 | 实际检索渠道、检索日期和原始来源核验状态 |
| 指定DM来源处理 | 在指定DM文件及披露窗口内匹配、核对和归并记录 | 源自DM；完成度仅代表指定数据集覆盖 |
| 已有证据增量核验 | 对指定事项、主体月份或证据缺口补证；按任务要求确定是否联网 | 本次补证结果、已有证据变更与剩余缺口 |

混合任务分别保存DM和联网证据及完成情况；后续找到官方原文时关联到同一事项，保留原DM定位。纯排版、PDF检查或无需补证的来源回写，转入 `credit-negative-monitoring` 的对应模式。

**完成条件：** 数据源、是否联网、处理范围和本次交付终点均已明确；不存在依靠技能名称自动扩大的检索或写回范围。

## 2. 冻结主体与月份范围

阅读任务说明和适用的 `AGENTS.md`，在指定根目录内定位准确文件。当前月度监控按 `1.准入授信后监测表`、`2.准入后监测表`、`3.简易准入后监测表` 分类存放；以实际目录和任务指定路径为准，排除归档、备份、临时载体和 `~$` 锁文件。

- 已有月表：提取实际监测行；任务同时指定冻结名单时，核对两者的主体、类别和有效月份，列出差异。新建月表：从任务指定的范围版本生成，记录版本、文件路径及哈希。当前名单不能替代历史主体月份范围。
- 将每个 `监测类别＋监测主体＋归属月份` 定为一个覆盖任务，关联目标文件、工作表和全部对应行。总行、具体分支行、部门、产品或计划分别保留其身份；名称变体仅用于检索和有依据的关联。
- 记录监测归属月份、披露窗口、实际制作日期和名单版本。默认使用归属月份的完整自然月，按公开披露日期归月；文件名或制作月份不改变窗口。历史补查按各主体的有效月份逐项核对。
- 在采集前读取 [监测规则](../credit-negative-monitoring/SKILL.md) 的“证据范围”，按监测类别确定关联主体边界；准入后表中存放同业行特别执行“准入后存放同业的主体边界”。

**完成条件：** 每个覆盖任务有唯一身份、窗口和目标定位，输入文件已留存基线；范围差异均有处理结果或列为待确认。仅暂停受冲突影响的任务，其余已确定范围继续处理。

## 3. 采集候选并保存过程

- **联网检索**：读取 [联网检索策略](references/online-search.md)，使用可用的 `agent-reach` 技能及检索能力，先做一次最小只读查询验证。按主体和风险事项选择渠道，逐家执行；有线索或覆盖缺口时定向补查。
- **指定DM来源**：检查原始文件表头和披露日期字段，筛选本次窗口；按冻结主体及有依据的关系映射匹配，保留原始记录定位与去重对应关系。文件未包含的风险类型列为数据源范围限制，不自动扩展为互联网任务。
- **已有证据增量核验**：以指定缺口清单为工作队列，保留已核实事实和既有覆盖记录；仅更新本次取得证据支持的字段与判断。

在独立过程记录中保存实际执行的查询或筛选、渠道、时间、候选及错误，按 [证据记录与对账](references/evidence-and-reconciliation.md) 关联到覆盖任务。沿用现有JSONL和逐家记录工作簿；新建时保存可复核的明细及按任务汇总的可读表，不为同一数据重复制造多套台账。

**完成条件：** 范围内每个任务都有实际执行记录或明确缺口；所有候选均可定位。已知事件补证与面向整个范围的新增发现分别记录，不能互相替代。

## 4. 核验证据并完成列示判断

本技能维护采集过程和证据对账；业务口径按下表读取，在本次流程中执行对应阶段。已经完成的范围和采集阶段直接沿用，不因技能互相引用而重新启动。

| 判断阶段 | 权威规则与现有实现 |
|---|---|
| 来源等级、主体关联、一般纳入条件 | [监测规则](../credit-negative-monitoring/SKILL.md) 的“来源优先级”“证据范围”“纳入规则” |
| 重点银行处罚归并与分层 | 上述技能的“重点银行处罚分层”及其指向的参考文件；项目如提供 `tools/monthly_monitoring_policy.py` 和 `tools/monthly_monitoring_categories.py`，核验后复用 |
| 来源字段、逐人对应、去重与覆盖 | 上述技能的“来源归集工作簿” |
| 摘要、姓名脱敏、文号、排序、结论和版式 | 上述技能的“月度监测表回写”“基本结论规则”“Excel 处理”“排版和 PDF”“定向质量门禁”；项目如提供 `tools/monthly_monitoring_formatting.py`，核验后复用 |

调用已有程序前检查其接口、输入路径、适用范围和写入行为。只将有证据支持的事实及已完成的复核结果传入判断，缺失金额、身份或职务保留缺口，不能让程序默认值充当已核实事实。业务规则以当前监测技能及其参考文件为准；如共享执行结果与规则存在差异，记录差异并暂停受影响的回写，保持其他任务继续。权威规则不可读时完成可独立进行的采集，列示判断保留待处理。

按 [证据记录与对账](references/evidence-and-reconciliation.md) 建立候选、来源、独立事项与目标行之间的对应关系，并顺序完成：

1. **来源核验**：联网候选打开正文或附件，保存能支撑事实的原文定位；按权威规则判定证据等级。DM记录核对指定文件、工作表和行，标记为DM证据，不赋予独立官网核验状态。
2. **主体与月份核对**：核实事件主体与目标主体的直接关联以及披露日期。范围外事项保留真实月份和不回写原因；身份或日期不明确时保留待核实。
3. **独立事项归并**：先按证据确认同一事项，再关联机构、责任人及多份来源；为每次合并保留依据。逐人保存完整姓名、官方披露的职务和处罚对应关系。
4. **列示判断**：对已核实事项应用上表规则，保存列示、仅归集或待复核决定及依据。对“同一事实链条”“直接相关业务”“核心高管”等判断保留事实证据，按规则要求完成复核。

**完成条件：** 每条候选均有核验结果、明确排除原因或待处理状态；每项已核实事件均有主体、月份、归并和列示依据。采集数量、可访问链接或程序分数本身不构成事实核验完成。

## 5. 增量归集与回写

在已授权的范围内生成变更清单，区分新增来源、补强/修正既有来源、正式新增和正式修订。按监测技能的来源字段与去重规则增量更新，保留现有表头、列顺序、历史记录和非目标月份；过程记录与来源归集表各自维护，已有月份工作表按覆盖任务更新。

唯一原件或已有业务文件发生原位修改、替换前，将受影响文件备份到带任务主题和时间戳的 `archive/` 目录，并核对副本可恢复。批量更新先在独立暂存目录处理并验证，通过后发布到明确的交付路径；覆盖原件必须在用户授权范围内。保留文件清单及哈希；存在Excel锁定或未保存内容时保留暂存成果，按监测技能处理，不强制替换。

将已决定列示事项、证据映射及无待处理缺口的覆盖任务交给监测技能的回写与展示阶段。摘要、完整未发现表述和基本结论由其现行规则及共享实现生成；调用格式化程序后核对模板、非目标内容和打印设置。

**完成条件：** 每条拟变更均落到实际文件和行，来源、独立事项与正式行互相可追溯；本次以外的业务字段和历史内容保持不变，待处理任务未被输出为已完成的“未发现”结论。

## 6. 验收与交付

执行 [证据记录与对账](references/evidence-and-reconciliation.md) 的双向验收和计数规则，并核验本次实际交付文件：

- 冻结任务与过程记录逐项对账；正式列示逐项追到原始来源，已核实来源逐项追到处理决定。
- 复核本次新增或修订的列示依据；统计按类别、月份和数据源模式拆分，分别报告原始记录、独立事项、来源新增/补强和正式回写。
- 对业务工作簿检查ZIP完整性、重新打开、表头结构、超链接、目标值和非目标差异；Windows Excel可用时对最终业务文件只读重开，正式监测表检查打印预览或导出的PDF。发布后的文件再次核对哈希和关键内容，暂存副本的通过不能代替正式交付验收。
- 按监测技能的定向质量门禁核对本次适用规则；无法运行的验收明确列为未验证。

在现有配套材料位置保存执行说明，批量任务可用一份逐月汇总，包含模式、范围版本、窗口、分阶段计数、不回写原因、缺口、文件及备份路径和验收结果。仅检索或核验任务交付相应证据与对账，不伪造回写记录。

**完成条件：** 用户要求的交付阶段已完成且有对应验收；所有缺口均准确反映在状态和计数中。仍有影响该阶段完成的缺口时，交付已完成部分并明确未完成范围，不宣称全量完成。

最终回复列明实际文件、备份、是否联网、来源新增/补强与正式新增/修订数量、验收结果和剩余问题，以及是否修改全局配置或执行Git暂存、提交、发布。
