# 联网检索策略

仅在本次任务包含联网检索或联网补证时读取。主体边界、证据等级和纳入条件以主文件指向的监测规则为准；本文件只规定如何取得可核验来源和记录覆盖。

## 渠道与查询

环境已提供 `agent-reach` 时先读取其渠道指引；随后检查本次实际可调用的搜索、浏览器或公开页面读取能力。未安装该技能时直接检查现有检索能力。用一个目标主体进行只读查询，并打开一份结果正文验证链路。诊断命令只在能力不明或调用失败时使用；工具名称及过去可用的本地服务不是当前可用性证据。

按主体类型选择适用渠道，并在过程记录中说明所查范围：

| 事项范围 | 常用原始来源渠道 | 查询线索 |
|---|---|---|
| 银行、保险等机构审慎监管事项 | 金融监管总局及派出机构 | 行政处罚、监管措施、罚款、责令改正及机构名称 |
| 人民银行监管事项 | 人民银行及分支机构 | 行政处罚公示、账户、支付清算、反洗钱、征信、金融统计及机构名称 |
| 外汇监管事项 | 国家外汇管理局及分局“管理信息”、外汇行政处罚查询 | 外汇处罚、结售汇、跨境收付、资本项目、国际收支申报及机构名称或统一社会信用代码 |
| 证券、基金与资本市场事项 | 证监会及派出机构、交易所、相关自律组织 | 警示函、监管措施、纪律处分、市场禁入 |
| 银行间债券市场事项 | 交易商协会等相关自律组织、发行人披露渠道 | 自律处分、债券、同业、资金、违约或评级行动 |
| 管理层任免与重大人事调动 | 机构官网新闻及投资者关系公告、交易所披露、主管部门或组织部门发布、监管任职资格批复 | 董事长、党委书记、行长等职务结合任免、调任、辞任、聘任、代为履职、任职资格及生效日期 |
| 管理人员调查及司法事项 | 纪检监察机关、法院、检察院、公安机关及机构公告 | 调查、起诉、判决、重大诉讼及已知人员职务 |
| 机构经营与声誉事项 | 机构/发行人公告、正式评级披露；媒体用于发现线索 | 评级负面行动、违约、重大经营事件和舆情 |

每家机构至少执行名称检索及适用的监管、司法/管理层、信用/重大舆情方向；对不适用方向记录依据。官网检索与通用搜索可以配合，具体组合由实际渠道覆盖决定。

用户点名人行、金监局、外汇局或人事信息时，为各渠道分别保留实际查询和结果。人事任免使用独立查询，不仅与处罚、调查等负面词组合。机构当前领导名单只支持职务状态，不能单独证明某月发生任免；以有日期的公告正文或附件核对人事事件。

使用机构全称及已核实简称，结合监测年份、月份和相关风险词检索；必要时去掉月份词，改用官方列表日期筛选，避免公告未被月份词索引造成漏检。分支机构、人员和业务条线关键词服从冻结主体边界；福建等地域词只在任务范围适用时使用。

历史多月可合并检索连续窗口，再按原始披露日期拆分到任务月份；过程记录须能证明每个主体月份的覆盖。查询命中旧闻时追溯原始披露时间，新转载日期不自动形成当期新事件。

## 专项原文与日期核对

- **人行**：分别提取页面发布时间和表内处罚决定日期；按机构行核对罚款与没收违法所得，个人记录另行关联。
- **金监局**：含 `{{data...}}` 等模板占位符的页面视为未取得正文。对已发现的 `docId`，可尝试官方静态详情路径 `https://www.nfra.gov.cn/cn/static/data/DocInfo/SelectByDocId/data_docId={docId}.json`，核对返回成功状态、`docId`、`docSubtitle`、`publishDate` 与 `docClob`，保留动态页面和实际读取路径；仅获取已发现编号，不遍历猜测编号。
- **外汇局**：逐条区分违法事实、法规条款、处罚决定日期、公示截止期和公开披露日期。查询页面的通用更新时间或搜索引擎推定日期不作为事项披露日期；缺少明确披露日期时保留待补证状态，也不从公示截止期倒推。只有罚没合计时保留合计，不拆造罚款与没收金额。
- **人事**：打开公告正文及必要附件，分别记录任免决定、任职资格核准、就任/辞任生效和公告日期，核对姓名、机构、原职、新职及明确披露的原因。各日期缺失时保持缺失，是否属于正式监测列示事项仍执行权威纳入规则。

## 定向补查

候选的主体、日期、文号或职务不完整时，围绕缺失事实补查：使用准确文号、处罚机关、人员姓名或具体分支机构名称，进入相应官方栏目及附件。对已有处罚或事件的补证不能代替其他风险方向的搜索。

搜索结果、AI摘要和媒体转载只作为定位入口；将相关候选带入主文件的来源核验阶段。取得正文或附件后，检查标题、主体、披露日期和实际内容；站点首页、搜索页、空壳页与验证码页记为未取得正文。

同一原始来源可支持多个覆盖任务：正文只取一次，保留任务关联和核验时间。复用缓存时记录原抓取日期、来源网址和文件定位；缓存支持证据复核，但不能替代用户要求的当期新检索。

## 访问失败与恢复

对监管网站等渠道低频访问，使用缓存、低并发和失败退避。开始批量采集前，依据站点限制设置有限的重试上限并记入执行记录；达到上限后记录失败并转入替代渠道或待处理。

动态页面访问失败时，可通过官网目录、官方静态详情、原始附件、公开官方镜像或可用浏览器取得同一来源；另存实际访问路径及最终原始来源位置。使用已有脚本前核对限频、扫描范围和输出路径，采用与本次主体及时间窗口相符的最小范围。

遇到403、验证码、限流或正文缺失时，不把空结果当作无事项。记录未覆盖的主体、渠道、时间窗口、已尝试方式和可继续补查的路径；停止该渠道的重复尝试，继续其他独立任务。

## 检索完成标准

每个覆盖任务具备实际执行时间、查询或官方栏目范围、渠道、结果和补查记录；计划内适用方向均已执行，相关候选均已进入核验或有明确排除依据。访问缺口仍保留在任务状态中；只有满足主文件和证据对账文件的全部完成条件，才能计入完整处理数。
