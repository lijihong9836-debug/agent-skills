# 证据记录与对账

在建立过程记录、归并事项或验收增量回写时读取。以下是逻辑记录要求，优先映射到现有字段；缺少的过程信息放入配套台账，保持业务工作簿结构不变。

## 四种记录与关联

| 记录 | 标识与必要信息 | 对应关系 |
|---|---|---|
| 覆盖任务 | 监测类别、冻结主体标识或可唯一定位的名称、归属月份；范围版本、窗口、目标文件/表/行、工作模式 | 同一任务可以关联多条查询、多份来源和多项事件；同一主体在不同类别或月份分别计数 |
| 采集与候选 | 任务标识、执行时间、查询/筛选条件、实际渠道或DM文件定位、执行结果、候选标识、失败与补查记录 | 未实际执行的查询保持未执行；计划关键词不能充当执行证据 |
| 原始来源 | 来源标识、层级/类型、网址或文件/工作表/行、原始披露日期、原文定位、事实字段、核验状态 | 一份来源可包含多个事件；同一事件可以有多份来源；DM与后补官网证据均保留 |
| 独立事项 | 稳定事项标识、主体、披露日期、归并依据、关联来源、列示决定及理由、复核状态、目标任务与行 | 机构和个人记录关联到事项；每项已核实事件均可追到原始证据及处理决定 |

沿用现有可靠标识。没有标识时，在本批次台账分配并保存稳定标识；后续补链接或修正简称沿用该标识。依照监测技能的保守去重规则复核重复候选，无法确认同一事项时保留疑似关系，暂不合并。工作簿行号是定位信息，不能单独作为跨版本事件标识。

## 核验所需事实

联网证据记录正文、处罚决定书或PDF的具体段落、页码、表格位置或可复核的文本摘录；处理图片型公告时保留原图定位并核对识别结果。HTTP成功、标题命中或链接可访问只证明访问状态。

处罚事实至少核对：被处罚主体、披露日期、处罚机关、主要违法违规事实、措施、金额与文号；按来源实际披露情况分别记录机构罚款、机构没收违法所得、个人罚款及人员职务。缺失字段保留缺口，列示资格交给权威规则判断。非处罚事件核对日期、主体、核心事实及已披露的处理结果。

日期按原始字段含义保存：公告/公开披露日期、处罚决定日期和任免生效日期分别记录；栏目更新时间、网页抓取日期或公示截止期不能填入事件披露日期。原文仅有合计金额或已脱敏姓名时，保留其原貌，来源字段的完整性要求不构成补造分项金额或还原姓名的依据。

人事事项分别记录变动事实与负面风险判断。有日期和原文支持的任免可以核验为人事信息；是否进入负面监测表继续依权威纳入规则及本次任务范围判断，不能仅凭“任命”“辞任”字样自动标成负面事件。

DM证据保留原始文件名、哈希、工作表、行号及相关字段原值，核验状态写明“已核对DM原始记录”。来源标签遵循监测技能；没有官网原文时不推测网址或官方职务。后来取得原始来源时，另记核验时间、定位及与DM记录的差异，保留原证据。

## 状态与完成条件

覆盖任务分别记录两类状态：

- **采集状态**：未执行、进行中、已完成、存在访问/数据缺口。
- **事项处理状态**：待核实、待复核、已决定列示、已决定仅归集、已排除；回写再单列未写入、已写入和验收结果。

每条候选注明后续去向。排除原因应能复核，例如主体不符、披露期外、重复候选（关联保留项）或不满足纳入规则；无法访问、日期不明、主体关联不明均属于待处理。

仅当覆盖任务已完成所选模式的采集、相关候选均处理完毕，且没有符合正式列示条件的事项时，才可按监测技能生成“未发现”类正式表述。已核实但仅归集的处罚与“未发现符合正式列示条件的事项”可以并存。未解决且可能改变列示判断的缺口使该任务保持待处理，不生成新的“未发现”结论。可交付已完成部分和缺口清单，但不能将该任务计入完整监测完成数。

DM覆盖完成只说明指定数据集内的匹配与处理完成。仅针对几个事项的增量核验，只报告这些事项的完成情况；沿用其他既有覆盖时注明其来源版本和检索日期，不冒充本次新检索。

## 增量与幂等

写入前将每条变更归为新增来源、补强既有来源、修正既有记录、来源关联、正式新增或正式修订。建立原记录到新记录的映射；同一事项新增官网链接通常属于证据补强，不因此新增正式事件。

对已有来源表按其固定表头及监测技能的覆盖键逐条核对。新增字段须遵循既有结构授权；源文件和已核实历史事实保留可追溯原值。一个文件中多类监测或同一月份的非本次范围记录保持不变。

重复运行相同输入、范围与规则时，先与已保存标识和变更记录对账；应无重复来源、重复独立事项或重复正式回写。出现新的证据或事实修订时，仅形成有依据的增量。

## 双向验收

1. **范围对账**：冻结任务集合与过程记录的唯一任务集合相等，并分别列出未执行、存在缺口和完整处理的任务。多余任务、缺失任务和重复任务分别报告；总行数相同不代表覆盖一致。
2. **列示到来源**：本次范围内每条正式非“未发现”行均能匹配来源记录，并能拆解至实际列示的独立事项。检查目标工作簿、工作表和行；同一月份多类表的行号不可混用。
3. **来源到决定**：每项已核实事件均有列示、仅归集或待复核状态。已决定列示的事项必须定位到实际交付行；未回写的逐项列明原因或阻碍。
4. **统计对账**：对每个类别和月份分别比较正式列示的独立事项、机构数和机构罚没合计；金额与计数按监测技能规定的列示口径计算。来源记录和个人文号不充当独立事项。
5. **变更对账**：对比输入基线与实际交付文件的主体、类别、准入/授信日期、额度、评级、行顺序、表头及非目标数据；所有差异均属于已授权变更。证据缺口和历史未匹配行逐项列明，不用本次新增来源掩盖。

## 交付计数

按“类别＋月份＋模式”提供以下适用计数，注明计数单位：

- 应覆盖任务、实际执行任务、完整处理任务、缺口任务；
- 候选条数、已核验原始页面数或已核对DM记录数、待核验候选数；
- 新增来源记录、补强/修正既有来源记录；
- 已核实独立事项、决定列示事项、仅归集事项、待复核事项；
- 正式新增事项、正式修订事项、涉及机构数、尚未回写事项及原因。

网页数、来源行数、独立事项数和正式表行数之间是多对多关系，分别对账。只补强既有链接时，新增来源与新增事件按实际情况计数；实际没有新增事件时明确为零。
